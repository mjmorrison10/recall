# RECALL: AI ops UX — timers on transcribe/compose, thinking toggle, timeouts

## Goal
Stack-wide retrofit (3 of 4, after BLAST and HOOKLAB): request timeouts so a
hung connection can't freeze a button, the elapsed-timer + learned
"typically ~Ns" pattern on transcription and AI COMPOSE, a thinking toggle
(default ON), and persistent in-app failure notes. Top Clips scanning already
has its own timer (recall_tc_ai_ms_v1) and MUST keep thinking regardless of
the toggle.

## Facts
- llm.js already has thinking opts in geminiGenerateText (the Top Clips arc
  added them); it has NO fetch timeout anywhere.
- Transcription progress uses setModalStatus("progress", …) via an onPhase
  callback; failures land in the catch as a persistent "warn" mstatus.
- aiComposePost sends maxTokens 600 with no thinkingConfig at all — Gemini
  does dynamic thinking against that tiny cap (silent truncation risk).
- Top Clips aiPass is pinned at thinkingBudget 4096 + maxTokens 16000 —
  thinking-off provably returned empty selections (the 7/22 arc).

## Changes
- **llm.js**: fetchWithTimeout (GEN 180s / UPLOAD_START 30s / UPLOAD 15min /
  POLL 15s) wrapping all 7 AI-path fetches; delete stays best-effort. Media
  path keeps hardcoded thinkingBudget 0 with a comment (transcription never
  thinks). No thinking-opts change (already present).
- **app.js**: `recall_ai_ms_v1` op-keyed duration store (transcribe/compose)
  + `recall_thinking_v1` + shared `aiThinking` (shared wins, default on,
  persisted on radio change); `aiTicker(op, baseText, write)` →
  {onPhase, elapsedS, stop(ok)}; msave transcription wrapped (ticker into
  setModalStatus, failure rethrown as "Transcription failed after Ns — …" so
  the existing persistent warn carries the elapsed time); openSettings
  re-reflects the pref; TopClips init deps gain aiTicker + getThinkingPref.
- **topclips.js**: aiPass UNCHANGED (comment says the toggle is deliberately
  ignored); aiComposePost toggle-aware (ON → thinkingBudget 1024 + maxTokens
  2048, OFF → 0 + 600) and threads onPhase; compose button click wraps with
  aiTicker("compose") ticking into the button label + persistent .postainote
  failure line in the panel (cleared at next run start).
- **index.html**: "AI speed vs. quality" radio row in the settings modal
  between the provider block and #geminiFields.
- **style.css**: .postainote rules (gold, matching .mstatus.warn).

(0 + 600) is exactly today's behavior minus dynamic thinking; ON gives it a
